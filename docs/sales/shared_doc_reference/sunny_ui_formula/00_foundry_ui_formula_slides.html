Sunny's Foundry System

The UI Formula

A deterministic method for converting a task specification into a working screen. Given the task and its screen plan, the formula draws the screen without design decisions at build time.

task-card.json → screens.json → Working Screen

Source: "Foundry Task Kit" + "Foundry Task Screens" artifacts by Sunny

Slide 2

Five tiers, one direction

Small atoms compose into bigger pieces, all the way to the screen.

1

30 Primitives

Carbon Design System atoms: Button, TextInput, DataTable, etc. Each maps to exactly one Carbon component.

2

41 Components

Named UI pieces that do one job in a task. Made of 2–6 primitives. Grouped: shell, frame, select, record, analysis, entry, commit, send.

3

11 Patterns

Named screen arrangements (FD-01 – FD-11). Each defines required/optional slots and has variants that set the regions.

4

9 Slots

The fixed positions on every screen (a CSS grid). Every component sits in exactly one slot.

5

6 Placement Rules

Rules that decide which region a component goes into and how it behaves. Deterministic: same input, same screen.

Slide 5

6 Placement Rules

Once patterns set the regions, these rules decide where each component sits.

Rule 1

The main work gets the largest region

Rule 2

What is compared together stays visible together

Rule 3

A warning sits next to what it is about

Rule 4

The commit sits at the point of decision

Rule 5

Background goes lowest

Rule 6

Fit the device

Example (Rule 3): In Record a Delivery (SOI-T02), the 200 kg tolerance warning sits inside the PO line it is about, not in a banner at the top. Even on a phone, the warning stays inside that line.

Slide 6

The conversion: spec to screen

"Draws the regions, then places each step's components, then marks the placement rules. Then the screen works."

1

Choose pattern(s)

Match the task's characteristics (volume, complexity, urgency) to one of the 11 patterns.

2

Choose the variant

Each pattern has variants for specific conditions (queue vs single, desk vs phone).

3

Draw the regions

The variant defines 2–3 regions with column widths out of 16 and which slots they hold.

4

Place each step's components

Each component has a slot and region assignment, tied to its step(s) in the task.

5

Apply placement rules

Specific notes override general placement. The 6 rules pin how components sit.

Slide 10

How to use this formula for a new task

1

Write task-card.json

Who does the task, what triggers it, the steps, the characteristics, the endings.

2

Choose pattern + variant

Queue of items → Attention Queue. One record to enter → Structured Editor. Bulk review → Bulk Console. And so on.

3

List components per step

For each step, which components appear and in which slot.

4

Write placement notes

Apply the 6 rules to pin where components sit within their region.

5

Write screens.json and convert

Draw regions, place components, apply rules. The screen works.

Key insight: The formula is deterministic. Same task-card + same screens.json = same screen, every time. No design decisions at build time. The design decisions are encoded in the patterns, the slots, and the placement rules.
